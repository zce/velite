# Make s.toc derive from an explicit input value

Status: ready-for-agent
Origin: #400 (deleted from GitHub)
Created: 2026-07-16T02:25:18Z
Labels: bug

---

## Problem

`s.toc()` accepts an explicit string input and checks that selected body for emptiness, but then always extracts headings from `context().file.mdast`. The result therefore describes the current file body instead of the explicit value. It can also fail with `No mdast tree available` when an explicit value exists but the file has no body.

Evidence: `src/core/schema/toc.ts` selects `value ?? file.content` but unconditionally reads `file.mdast`; `file.mdast` is created only from the file content in `src/core/schema/context.ts`.

## Expected behavior

When an explicit value is provided, derive the TOC from that value. Use the file-scoped cached parse only when no explicit value is provided.

## Design context

The long-term relationship between value transforms and file derivations is being decided in [Define the semantic invariants of shared content derivation](03-define-the-semantic-invariants-of-shared-content-derivation.md) and [Choose the public composition model for content derivations](04-choose-the-public-composition-model-for-content-derivations.md). This issue records the current contract violation without prescribing the 1.0 public model.

## Answer

> _This was generated by AI during triage._

**Verification:** Confirmed. `src/core/schema/toc.ts` computes `value ?? file.content` only for the empty-input check, then always reads `file.mdast`; `src/core/schema/context.ts` constructs that AST exclusively from `file.content`. An explicit value is therefore ignored for TOC derivation.

**Disposition:** `subsumed-by-design`.

**Design coverage:** Decision 03 defines Content Input as origin plus selected text, dialect, and parse-affecting configuration, with explicit text taking precedence over the file-body fallback. Decision 04 removes top-level `s.toc()` and exposes `.toc()` from Markdown/MDX roots. Decision 19 routes Velite-owned roots and projections through a private controlled broker capability and removes `ContentFile.mdast`, so the failing `file.mdast` access path does not exist in 1.0.

**Implementation constraint:** The 1.0 implementations of `s.markdown().toc()` and `s.mdx().toc()` in the content root/projection schema modules must submit a controlled request through the record-bound content capability. The request must carry the explicit schema input when present, otherwise the current file body, together with origin, dialect, and effective parse configuration. It must never derive an explicit-input TOC from a fallback file-body artifact.

**Acceptance test:** For both Markdown and MDX roots, provide an explicit value whose headings differ from the current file body and assert that `.toc()` describes only the explicit value. Then omit the explicit value and assert that `.toc()` describes the file body. The fake-capability request test must also assert the selected text, source path, dialect, and effective profile required by decisions 03, 04, and 19.
