# Process linked assets in inline MDX JSX elements

## Problem

The MDX linked-file plugin visits `mdxJsxFlowElement` nodes but not `mdxJsxTextElement` nodes. Relative asset attributes on inline JSX are therefore left unchanged even though the schema option describes linked files on MDX JSX attributes generally.

Example: `Text <Icon src="./inline.png" />` is not processed, while a block JSX element is.

Evidence: `src/core/content/asset-links.ts` registers only a `mdxJsxFlowElement` visitor.

## Expected behavior

Apply the same static string-attribute handling to both flow and text MDX JSX elements.

## Design context

The broader plugin contract is being decided in [Define plugin execution and isolation semantics](06-define-plugin-execution-and-isolation-semantics.md), part of [Design the 1.0 shared content derivation kernel](../map.md).

## Answer

> _This was generated by AI during triage._

**Verification:** Confirmed. `src/core/content/asset-links.ts` registers the current MDX JSX asset visitor only for `mdxJsxFlowElement`; no visitor handles `mdxJsxTextElement`, so inline static string attributes are skipped.

**Disposition:** `implementation-constraint`.

**Design coverage:** Decision 06 preserves ordinary plugin semantics and explicitly retains linked-asset form coverage as implementation work rather than changing the behavior through the 1.0 design.

**Implementation constraint:** `remarkCopyLinkedFiles` in `src/core/content/asset-links.ts` (or the 1.0 equivalent linked-asset transform) must visit both `mdxJsxFlowElement` and `mdxJsxTextElement` and apply identical relative-path and static string-attribute handling to `href`, `src`, and `poster`. Dynamic MDX attribute expressions must not be treated as static paths.

**Acceptance test:** Process `Text <Icon src="./inline.png" />` through the MDX linked-asset branch and assert that the callback receives `./inline.png` and the compiled output contains its returned public URL. Keep equivalent coverage for a flow JSX element and assert that a dynamic expression attribute is unchanged. This test enforces decision 06.
