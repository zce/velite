# Rewrite linked HTML asset properties independently

## Problem

`rehypeCopyLinkedFiles` records elements by URL, then rewrites every present `href`, `src`, and `poster` property on each recorded element. An element containing different relative URLs in multiple properties can have all properties overwritten with whichever processed URL completes last.

Example: `<video src="./video.mp4" poster="./poster.jpg">` can receive the same public URL for both properties. `Promise.all` makes the final value timing-dependent.

Evidence: `src/core/content/asset-links.ts` stores `Element[]` and loops over all `LINKED_PROPERTIES` during each URL replacement.

## Expected behavior

Track and rewrite each `{node, property}` occurrence independently. Each source URL must update only the property from which it was collected, with deterministic output regardless of async completion order.

## Design context

Plugin and effect semantics are being designed in [Define plugin execution and isolation semantics](06-define-plugin-execution-and-isolation-semantics.md) and [Define asset effects, diagnostics, and failure semantics](09-define-asset-effects-diagnostics-and-failure-semantics.md).

## Answer

> _This was generated by AI during triage._

**Verification:** Confirmed. `rehypeCopyLinkedFiles` in `src/core/content/asset-links.ts` stores whole elements by source URL, then each asynchronous replacement rewrites every present linked property on each stored element. Multiple relative properties on one element can therefore overwrite one another according to Promise completion order.

**Disposition:** `implementation-constraint`.

**Design coverage:** Decision 06 requires isolated plugin behavior independent of asynchronous completion order. Decision 09 requires occurrence-level effect provenance and canonical deterministic ordering rather than `collectEffect` or Promise timing.

**Implementation constraint:** `rehypeCopyLinkedFiles` in `src/core/content/asset-links.ts` (or the 1.0 equivalent transform) must track every asset occurrence as its exact `{ node, property }` association. Resolving a source URL may update only the property from which that occurrence was collected. Final output and associated effects must be deterministic regardless of asset callback completion order.

**Acceptance test:** Process `<video src="./video.mp4" poster="./poster.jpg">` with callbacks that resolve in both normal and reversed orders. Assert that `src` always contains the processed video URL, `poster` always contains the processed poster URL, and repeated runs produce identical output and occurrence associations. This test enforces decisions 06 and 09.
