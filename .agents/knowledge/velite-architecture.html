Velite 架构与扩展性设计

平台无关内核 · 运行时端口 · 显式工厂依赖注入

结论:先看全景

一句话架构

Velite 是三层合体:平台无关的领域层(src/core,纯派生图,零 node:* 导入);一组运行时端口(src/runtime,由 adapters/node 提供平台实现);显式工厂依赖注入(依赖在组合根可见、可测、可整体替换)。所有扩展点都是有限且显式注册的 API——没有运行时扫描、装饰器注入或隐藏注册表。

B

一、分层架构与组合根

依赖组装只发生在组合根。最关键的两个:公共门面 src/index.ts(安装进程级 Host、绑定全部 Node 适配器)与内部组合根 createBuilder(src/core/builder.ts,组装配置 + 加载器 + 管线 + 引擎 + 驱动)。

  • 公共门面 builder() 同时是 DI 接缝:fs / modules / logger / image / watch 全部在此绑定 Node 实现,测试可以整体替换。
  • watch 模式:文件事件先经 classify 路由(config / content / ignore)→ Scheduler 去抖串行 → Driver.applyChanges 增量补丁。
  • 配置变更 = 新 epoch(全新 Builder / Engine / Pipeline),因此配置与 schema 不需要哈希入图。
  • 独立构建天然隔离;构建期可变状态全部挂在 RunContext 上,会话级 schema 存储放 SessionStore。
C

二、构建管线:七条派生

createPipeline(src/core/pipeline/index.ts)把领域计算表达为七条 Derivation,由 Engine 按依赖拓扑求值:

  • 记忆化与陈旧性:输入未变直接命中缓存,输入变更标记陈旧后重算;in-flight 去重保证并发请求同一条派生只执行一次;环与缺输入是确定性 EngineError。
  • validate 是核心:加载结果 → SchemaRunner(为每条记录租用八字段上下文)→ 记录级内容执行模块(Parse / Transform / Emit 按需推进)。
  • emit 之后、写入之前,prepare 钩子介入(Driver 编排),再由 Output 层 planWrites(single / split 布局)落盘,写入时 hash 比对跳过未变更文件并清理陈旧输出。
D

三、运行时端口:平台隔离层

内核永远不触碰平台 API;端口类型定义在 src/runtime,实现在 src/runtime/adapters/node——这是全仓唯一允许 node:* 与原生导入的地方。

runtime 端口 ⇄ Node 适配适配器是唯一持有平台依赖的地方
  • FileSystemnode:fs + tinyglobby
  • ImageProcessorsharp(懒加载)
  • Logger控制台 · 分级日志
  • ModuleLoaderjiti · 运行时加载 velite.config.*
  • Watcherchokidar 文件事件
  • SchemaContextHostAsyncLocalStorage 载体传播 · 进程级
  • PromiseObserver原生 Promise 链沉降观察 · ADR 0003
  • 替换能力不需要改内核:换掉 ImageProcessor 适配器即可改用别的图片后端,内核与管线毫无感知。
  • 重型原生依赖(sharp)按需懒加载;jiti、sharp、zod、@mdx-js/mdx 是运行时依赖(external),其余工具打进 dist。
  • 每个适配器都是普通 createXxx() 工厂,在组合根被显式选中——没有反射、注册中心或环境探测。

内容定义的目标用法(ADR 0002,content 是独立命名空间,不进 s):

内容执行的共享不变量(ADR 0001 / 0002)

同一记录校验内「同一定义对象 + 精确选中的输入文本」共享一次独占执行;分开创建的定义永远独立。Parse 服务 Source Analysis(excerpt / metadata),完整 Transform 服务 Navigation TOC,Emit 服务 HTML / code;失败不重试,成功的低阶段保留。对外只交付脱离的语义结果(TOC 数组、元数据对象每次全新),绝不暴露 AST / VFile / 插件私有状态;关闭是终态且幂等。

UserConfig 是唯一的用户配置面;defineConfig / defineCollection 只做类型推断,零运行时效果。

值解析优先级

标量按 定义局部选项 ?? config.markdown / mdx 全局默认 ?? 内置默认 解析;显式 false 覆盖全局 true。插件注册:定义局部在前、全局在后,保序、不去重、不排序,按 Unified 原生 .use() 语义合并。运行期修改插件引用不受支持——变更请走配置重载(epoch 替换)。

六、context():八字段与唯一例外

context()(src/core/schema/context.ts)返回当前正在解析记录的八字段 SchemaContext——内置与用户自定义 schema 的能力边界完全相同,没有内部专属层:

project
解析后的配置快照(root · collections · output · 方言选项)
file
当前源文件(id · path;mdast/hast 已移除,自定义 schema 自带解析)
record
多记录源内的身份(id · key · index)
store
会话级 KV 存储;跨重建共享,配置重载时重置;刻意无 set()
collectEffect
声明 schema effect(两参声明面)→ 交 uniqueCheck 扫描
asset
按内容根相对 POSIX 路径解析资产;memo 化;返回 publicUrl + 可选图片元数据
readFile
直接读取资产字节(s.image({ absoluteRoot }) 使用)
probeImage
直接探测图片元数据(可加 blur),绕过资产管线
为什么允许这一个隐藏全局状态

Zod 的 transform 签名 (value, ctx) => ... 无法显式携带环境上下文,因此由进程级 SchemaContextHost 经 AsyncLocalStorage 传播 SchemaRunContext。同一 host 重复安装幂等;首次安装后再装不同 host 是确定性 VeliteError('internal');没有重置 / 替换 / 引用计数。host 只做传播,不持有 Builder、epoch、内容执行、缓存或注册表。除这一处,核心禁止一切隐藏全局状态。

七、设计红线

禁止模式 示例 原因
✗DI 容器 container.resolve(...) 依赖不可见 · 难追踪
✗服务定位器 services.user.getUser(...) 依赖隐式化
✗单例模块 export const userService = ... 测试与生命周期失控
✗装饰器注入 @injectable() / @inject() 依赖运行时元数据 · 隐藏布线
✗运行时自动注册 loadModules() / scanDirectory() 依赖隐式化
✗共享工具桶 common / shared / utils 无关职责堆积
✗隐藏全局状态 globalThis.xxx · 模块级可变状态 除非有意进程级(context host 是唯一例外)
✗依赖混入 execute({ db, logger, userId }) 构造依赖与业务输入生命周期不同
判据

必须用 createXxx(deps) 工厂 —— 满足任一即可:

  • 有依赖:文件系统 / 日志 / 图片 / 模块加载 / 观察器
  • 有状态:缓存 / 清单 / 引擎态 / 会话态
  • 有生命周期:dispose / close / 清理
  • 是组合模块或运行时适配器

允许直接导出:纯函数与工具、类型模块、常量、错误类、schema 构建器与恒等助手、公共门面。
